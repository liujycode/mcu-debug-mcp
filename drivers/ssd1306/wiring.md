# SSD1306 OLED 接线与避坑指南（0.96" I2C 128x64）

## 接线（4 脚 I2C 模块）

```
OLED             MCU (3.3V)
┌────────┐
│ VCC ─────────── 3.3V
│ GND ─────────── GND
│ SCL ─────────── I2C SCL（例：PB8）
│ SDA ─────────── I2C SDA（例：PB9）
└────────┘
```

## 头号坑清单

| 坑 | 症状 | 解法 |
|---|---|---|
| 电荷泵没开 | 初始化发了但屏全黑 | 0x8D 0x14 必须在初始化序列里（板载无升压电路的模块全靠内部电荷泵） |
| 显示顺序错 | 全黑/花屏 | 0xAF（display ON）必须最后发；反了有的批次不亮 |
| I2C 地址不对 | NACK | 0x3C 是绝大多数模块；扫到 0x3D 用 0x3D。注意有的手册写 0x78（8 位含写位） |
| 反色/上下颠倒 | 显示镜像 | 0xA1/0xC8 两行控制方向，装反了改这两条 |
| 刷屏慢/卡顿 | 帧率低 | I2C 提到 400kHz；整帧 1024 字节 @100kHz 要 ~100ms，@400kHz 约 25ms |
| 模块不接 VCC 只接 GND/SCL/SDA | 能亮但怪（靠总线寄生） | 必须接 VCC，寄生供电会导致随机花屏 |

## 显示测试万能招

初始化后发 `0xA5`（全点亮）：
- **全屏亮** → 接线和初始化都对，问题在你的显存内容/寻址
- **全黑** → 接线/地址/电荷泵问题，查硬件层

这个二分法排错思路答辩时讲出来很加分。

## 输出解读（配合本 MCP 的 analyzer）

- I2C 写 0x3C **NACK** → 命中 `I2C_NACK`：地址/接线/上拉
- I2C 扫描一个设备都没有 → 命中 `I2C_SCAN_EMPTY`：SDA/SCL 接反高发
- 屏亮但内容错乱 → 寻址模式（水平/页/垂直）与驱动实现不匹配

## 答辩加分点

1. **页寻址原理**：为什么 8 行共享 1 字节（y/8 分页 + y%8 位偏移）——讲清显存组织
2. **帧缓冲 vs 直写**：直写省 1KB RAM 但每像素一次 I2C 传输；帧缓冲一次刷屏——内存换速度的经典权衡
3. **刷新率计算**：1024 字节 ×9 bit（含 ACK）×帧率 = I2C 带宽占用，给出实测帧率
4. **中文字库**：ASCII 5x7 免字库，中文需 16x16 点阵字库（OLED 毕设加汉字显示的路径）
